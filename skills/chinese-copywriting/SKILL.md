# 中文文案排版

依《中文文案排版指北》統一中文文案的排版用法。

## 定位

只管**排版層**：空格、全形半形、標點形制、名詞寫法。

不動字句與內容。錯別字、文句潤飾、去除 AI 痕跡、翻譯都不屬於這裡的職責，遇到就說明並交給對應的工具。

## 模式一：校對

**絕不自動改檔，也絕不未經確認就開跑。** 校對對象與修正處置都要在動手前一次問清楚。

### 步驟 0：開跑前確認

跑腳本之前先用 `AskUserQuestion` 一次問完兩件事，取得答覆才進步驟 1。

**問題一：校對哪個檔？** 預設值取**編輯器當前開啟的檔案**（`ide_opened_file` 或 `ide_selection` 指到的路徑），把它放在第一個選項並標示「（當前開啟）」。使用者訊息已明確指定路徑時直接用那個，不必問。沒有當前開啟的檔案也沒有指定路徑就直接問要校對哪個檔，不要自行猜測。

**問題二：查完要怎麼處理？** 四個選項：

- **自動修正可安全處理的項目** — 跑 `--fix` 修規則 1-5、7，改完回報 diff 摘要；需人工判斷的項目另附建議清單
- **全部修正** — 先跑 `--fix`，語意項再用 `Edit` 逐處修改
- **只出報告，不改檔** — 停在清單，另附完整修正後文稿供貼上
- **先看清單再決定** — 出完報告停下來，等使用者指定編號才改

爭議規則預設不查；使用者明確要求才加 `--dispute`。

### 步驟 1 起：執行

1. 跑檢查腳本取得機械式違規清單：

   ```bash
   python3 skills/chinese-copywriting/scripts/check_copywriting.py --json <file>
   ```

2. 補上腳本判不出的語意項，逐條對照 [references/rules.md](references/rules.md) 的規則 9、10：專有名詞大小寫、不道地的縮寫、英文書名該用斜體而非中文書名號。
3. 輸出「排版違規清單」，每條含行號、原文片段、建議修正、依據規則，並標示可否自動修正。
4. 依步驟 0 談好的處置方式執行。選「先看清單再決定」就停在清單等指示。
5. 沒有違規就直接回報通過，不必再問。

**清單裡出現規則書本身的反例時不得修正。** 校對排版規則文件（例如本專案的 `README*.md`、`references/rules.md`）會大量命中 `錯誤：` 底下的示範句，那些是刻意寫錯的教材。回報時要把它們跟真違規分開列，並說明不動的理由。

改檔後必須回報實際改動筆數與 diff 摘要。

## 模式二：撰寫

產出中文文案時直接套用下方規則，不輸出報告、不詢問。寫完自我檢查一遍空格與全半形。

## 規則速查

| # | 規則 | 正確 | 錯誤 |
| --- | --- | --- | --- |
| 1 | 中英文之間加空格（含行內程式碼兩側） | `圍繞 AVObject 進行` | `圍繞AVObject進行` |
| 2 | 中文與數字之間加空格 | `花了 5000 元` | `花了5000元` |
| 3 | 數字與單位之間加空格 | `10 Gbps` | `10Gbps` |
| 4 | 全形標點與其他字符之間不加空格 | `iPhone，好開心！` | `iPhone ，好開心！` |
| 5 | 不重複使用標點符號 | `戰勝了巴西隊！` | `戰勝了巴西隊！！` |
| 6 | 使用全形中文標點 | `嗨！你知道嘛？` | `嗨! 你知道嘛?` |
| 7 | 數字使用半形字符 | `只賣 1000 元` | `只賣 １０００ 元` |
| 8 | 英文整句、特殊名詞內使用半形標點 | `「Stay hungry, stay foolish.」` | `「Stay hungry，stay foolish。」` |
| 9 | 專有名詞使用正確的大小寫 | `GitHub`、`Foursquare` | `Github`、`FourSquare` |
| 10 | 不要使用不道地的縮寫 | `TypeScript`、`HTML5` | `Ts`、`h5` |

規則 3 的**例外**：度數與百分比不加空格，寫 `90°`、`15%`，不寫 `90 °`、`15 %`。

完整的正誤範例與各條例外見 [references/rules.md](references/rules.md)。

## 爭議規則

以下兩條帶個人色彩，**無論是否遵循，從語法角度都是正確的**。預設不套用、也不報違規，只有使用者明確要求才處理：

- **超連結之間增加空格**：`請 [提交一個 issue](#) 並分配` 對比 `請[提交一個 issue](#) 並分配`
- **簡體中文使用直角引號**：`「有条不紊」` 對比 `“有条不紊”`

要一併檢查時給腳本加 `--dispute`。

## 例外

- **產品名詞按官方格式書寫**，例如「豆瓣FM」不補空格。腳本的豁免清單在 `scripts/check_copywriting.py` 頂端的 `EXCEPTION_TERMS`，遇到新的官方名詞就加進去。
- **設計稿、宣傳海報**中出現極少量數字、為方便文字對齊時，可以使用全形數字。
- **網頁需要全大寫或全小寫的視覺風格**時，HTML 裡仍寫標準大小寫，靠 `text-transform: uppercase;` 或 `text-transform: lowercase;` 呈現。
- **中文句子內夾英文書籍名、報刊名**時不借用中文書名號，改用英文斜體。

## 腳本

```
check_copywriting.py [--fix] [--json] [--dispute] <file>...
```

- 不帶旗標：只報告，有違規時 exit code 為 1
- `--fix`：就地修正規則 1、2、3、4、5、7；規則 6、8、9、10 一律只報告
- `--json`：機器可讀輸出
- `--dispute`：一併檢查爭議規則

腳本會自動跳過 fenced code block、縮排程式碼、行內程式碼內容、URL、Markdown 連結目標、HTML 標籤屬性與 YAML frontmatter。

腳本本身不做互動確認，這樣才能進 CI。**取得使用者同意前不得帶 `--fix`。**
