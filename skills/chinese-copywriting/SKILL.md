# 中文文案排版

依《中文文案排版指北》統一中文文案的排版用法。

## 定位

只管**排版層**：空格、全形半形、標點形制、名詞寫法。

不動字句與內容。錯別字、文句潤飾、去除 AI 痕跡、翻譯都不屬於這裡的職責，遇到就說明並交給對應的工具。

## 模式一：校對

**絕不自動改檔，也絕不未經確認就開跑。** 校對對象與修正處置都要在動手前一次問清楚。

### 步驟 0：開跑前確認

跑腳本之前先用 `AskUserQuestion` 一次問完兩件事，取得答覆才進步驟 1。

**問題一：校對哪個檔？** 預設值取**編輯器當前開啟的檔案**（`ide_opened_file` 或 `ide_selection` 指到的路徑），把它放在第一個選項並標示「（當前開啟）」。使用者訊息已明確指定路徑時直接用那個，不必問。沒有當前開啟的檔案也沒有指定路徑就直接問要校對哪個檔，不要自行猜測。

**問題二：查完要怎麼處理？** 四個選項：

- **自動修正可安全處理的項目** — 跑 `--fix` 修規則 1-5、7，改完回報 diff 摘要；需人工判斷的項目另附建議清單
- **全部修正** — 先跑 `--fix`，語意項再用 `Edit` 逐處修改
- **只出報告，不改檔** — 停在清單，另附完整修正後文稿供貼上
- **先看清單再決定** — 出完報告停下來，等使用者指定編號才改

爭議規則預設不查；使用者明確要求才加 `--dispute`。

### 步驟 1 起：執行

1. 跑檢查腳本取得機械式違規清單：

   ```bash
   python3 skills/chinese-copywriting/scripts/check_copywriting.py --json <file>
   ```

2. 補上腳本判不出的語意項，逐條對照 [references/rules.md](references/rules.md) 的規則 9、10：專有名詞大小寫、不道地的縮寫、英文書名該用斜體而非中文書名號。
3. 依〈報告樣板〉輸出「排版違規清單」，每條都要帶引用參考。
4. 依步驟 0 談好的處置方式執行。選「先看清單再決定」就停在清單等指示。
5. 沒有違規就直接回報通過，不必再問。

**清單裡出現規則書本身的反例時不得修正。** 校對排版規則文件（例如本專案的 `README*.md`、`references/rules.md`）會大量命中 `錯誤：` 底下的示範句，那些是刻意寫錯的教材。回報時要把它們跟真違規分開列，並說明不動的理由。

改檔後必須回報實際改動筆數與 diff 摘要。

## 模式二：撰寫

產出中文文案時直接套用 [references/rules.md](references/rules.md) 的規則，不輸出報告、不詢問、不附引用參考。寫完自我檢查一遍空格與全半形。

## 規則與引用來源

規則本體、行號引用、例外與爭議規則全部在 [references/rules.md](references/rules.md)：

- **規則索引**：12 條規則的名稱、上游行數、所屬章節
- **例外索引**：5 條例外各自對應哪一條規則、出自哪幾行
- **規則細則**：每條的完整正誤範例

校對前先讀那份，不要憑記憶引用行號。

爭議規則（11、12）預設不套用也不報違規，使用者明確要求才加 `--dispute`。產品名詞的豁免清單在 `scripts/check_copywriting.py` 頂端的 `EXCEPTION_TERMS`，遇到新的官方名詞就加進去。

## 引用規範

**每一條違規都要附引用參考，指回唯一事實根據**：

<https://github.com/sparanoid/chinese-copywriting-guidelines/blob/master/README.md>

格式是規則名稱接行數，中間一個半形空格：

```text
{規則名稱} L{起始行}-L{結束行}
```

例如 `數字與單位之間需要增加空格 L52-L74`、`使用全形中文標點 L118-L136`；只涉及單行時寫成 `L38`。行數一律查 [references/rules.md](references/rules.md) 的索引，不要自行推算。

引用的是規則所在的那幾行，不是違規文字所在的行——違規位置寫在清單的行號欄。

## 報告樣板

校對結果照這個結構輸出，欄位不增不減。樣板本身也遵守上列規則：

```markdown
## 排版違規清單

來源基準：sparanoid/chinese-copywriting-guidelines README.md（commit `bd7873c`）

| 行號 | 規則 | 原文片段 | 建議修正 | 引用參考 | 可自動修正 |
| --- | --- | --- | --- | --- | --- |
| L30 | R1 | `在LeanCloud上` | `在 LeanCloud 上` | 中英文之間需要增加空格 L22-L38 | 是 |
| L60 | R3 | `10Gbps` | `10 Gbps` | 數字與單位之間需要增加空格 L52-L74 | 是 |
| L182 | R9 | `Github` | `GitHub` | 專有名詞使用正確的大小寫 L166-L198 | 否 |

## 不予修正

| 行號 | 內容 | 理由 |
| --- | --- | --- |
| L128 | `嗨! 你知道嘛?` | 規則書的反例，刻意寫錯 |
```

沒有違規時只回報通過與所依據的來源基準，不輸出空表格。「不予修正」那節沒有內容就整節省略。

## 腳本

```
check_copywriting.py [--fix] [--json] [--dispute] <file>...
```

- 不帶旗標：只報告，有違規時 exit code 為 1
- `--fix`：就地修正規則 1、2、3、4、5、7；規則 6、8、9、10 一律只報告
- `--json`：機器可讀輸出
- `--dispute`：一併檢查爭議規則

腳本會自動跳過 fenced code block、縮排程式碼、行內程式碼內容、URL、Markdown 連結目標、HTML 標籤屬性與 YAML frontmatter。

腳本本身不做互動確認，這樣才能進 CI。**取得使用者同意前不得帶 `--fix`。**
